# #232 trace-r1 PC接続・初回2起動の解析

ユーザー報告: 1回目は全面白、2回目は正常。PC接続で取得する予備試験への回答として受領。
実際の給電配線、今回のtime set実施有無、表示判定秒数は添付ログには記載されていない。
AC給電の既報5/10との白率比較には使わない。

## 入力と検証

- `boot-1-white.txt` / `boot-2-normal.txt`: 添付からBOOTTRACE232ブロックを無改変抽出。
- 同名JSON: `scripts/issue232-trace/read_log.py` による解析結果。
- 両方ともv=23201、fnv=E10C55EFで配布manifestと一致。26行、記録24点、通番欠落なし、警告なし。
- PROVISIONの2点だけseq=0。両方とも初期化済み判定なので、これは期待した未実行経路。
- 全記録epoch=0、取得時epoch=1、fault=0、probe=4。今回の対になる記録点の間にDWTリセットはない。

## 同じ順序・ほぼ同じ時間で白と正常が分かれた

| 観測 | 1回目・白 | 2回目・正常 |
|---|---:|---:|
| RTC判定 | 初期化済み | 初期化済み |
| RCR1 / RCR2 / RCR4 | 00 / 41 / 00 | 00 / 41 / 00 |
| SOSCCR / SOMCR（BSP後） | 00 / 00 | 00 / 00 |
| GLCDC開始完了・OS時刻 | 60 ms | 60 ms |
| 初期黒バッファ設定完了・OS時刻 | 80 ms | 80 ms |
| RTC初期化開始／終了・OS時刻 | 460 / 460 ms | 460 / 460 ms |
| RTC初期化区間・DWT差 | 10,894 cycles | 10,922 cycles |
| RTC時刻取得区間・DWT差 | 1,740 cycles | 1,740 cycles |
| 最初の描画バッファ提出完了・OS時刻 | 2,530 ms | 2,530 ms |
| バックライト要求復帰・OS時刻 | 2,530 ms | 2,530 ms |
| 最初のVsync待ち開始／終了・OS時刻 | 2,550 / 2,560 ms | 2,550 / 2,560 ms |

OS時刻は稼働時間の10ms量子化値で、電源投入からの厳密な時刻ではない。
1GHz換算でRTC初期化区間は10.894 / 10.922 µs相当、差は28 cycles。
計測オーバーヘッドや割込みを含むサイクル差であり、厳密な壁時計時間・CPU専有時間とはしない。

RTC init/Open/Get、GLCDC Open/Start、初期バッファ提出、最初の描画バッファ提出、
バックライト要求、Vsync待ちの記録済み戻り値は両回とも成功。
DISPLAY_ENDの1はboolの成功。SYNCの0は成功を検査した値ではなく処理復帰の印。
根拠: `scripts/issue232-trace/overlay.py:31`以降の各API前後の挿入点と、上記の生ログ／JSON。

実行順序は両回とも「GLCDC開始 → 初期黒バッファ設定 → RTC初期化 → 最初の描画バッファ提出
→ バックライト要求復帰 → Vsync待ち復帰」。
RTCの初期化済み判定はSTART && HR24で、真の場合クロック源設定を省略する
（診断用コピー `e2studio_CPU0/Debug/issue232/trace-r1/e2studio_CPU0/src/time_ctrl.c:181,564`）。
採取レジスタは判定直後・BSP後の値であり、保持全体の健全性やBSP前の状態は証明しない
（`scripts/issue232-trace/boot_trace.c:65`）。

## 結論と残る範囲

今回の白起動では、RTC初期化の停止や、正常起動と比べた大きな所要時間差は観測されなかった。
「RTC初期化で止まって最初の描画に届かない」という説明は今回の白ログには当てはまらない。
保持なしの起動は測っていないので、保持有無の影響やRTC全体の関与を否定する結果ではない。

白でも描画バッファの提出と最初のVsync待ちからの復帰には到達した。
flushはBufferChangeの戻りを、WAITはセマフォ待ちの戻りを記録する。
ライン検出コールバックがセマフォを通知する実装だが、これらはパネルの受信・表示成功を証明しない
（`e2studio_CPU0/src/port/lvgl_port_mtk3.c:217,277,312`、挿入点はoverlay.py）。
記録は初回だけなので、その後の継続描画の健全性も未確認
（`scripts/issue232-trace/boot_trace.c:41,57`）。

次の調査対象は、白のまま稼働中の描画継続状況、GLCDC出力状態、パネル側の状態。
#230の既存切り分けと照合して追加観測を絞り、単純な待ち時間延長にはまだ進まない。
既存の2回分で今回のログ取得試運転の目的は達成した。
