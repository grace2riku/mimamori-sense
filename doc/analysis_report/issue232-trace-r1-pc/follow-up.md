# #232 追加調査：初回描画後の状態

実測追記: 追加2回（白・正常）の取得完了。白でもFlush 21 fps / Vsync 71 Hz、正常は20 fps / 71 Hz。レジスタ出力全文一致、両回ともバッファ標本は白一色ではなかった。結果と限界は `follow-up-results/README.md`。以下の取得手順は実施済みであり、再取得依頼ではない。

## コード調査結果

trace-r1の既存コマンドで追加取得できるため、この段階で新しい診断版は作らない。
起動処理・保持状態・フラッシュ配置を変えずに、今回の白が#230の既報と同じ故障状態かを確認する。
既報は `doc/design/white-screen-boot-regression.md:1725`（D-2、Vsync 71 Hz / Flush 20 fps）。
過去の全切り分け、待ち値変更、リセット順序変更、各タスク停止を再実行する計画ではない。

以下のソースパスは通常CPU0版。trace-r1の変更は記録点の追加で、下記コマンド本体は維持されている
（`scripts/issue232-trace/overlay.py`）。

| 取得 | 根拠 | 分かる範囲・限界 |
|---|---|---|
| `display dbuf` | `e2studio_CPU0/src/port/glcdc_port.c:578`、呼出分岐2486 | 1秒のtk_dly_tsk前後のFlush/Vsyncカウント差。レートはその窓の概数で、過去の起動全区間ではない |
| Flush / エラーの書き手 | 同2411、`src/port/lvgl_port_mtk3.c:277` | BufferChange復帰時に計数。要求数でありパネル表示フレーム数ではない |
| Vsync / underflowの書き手 | `src/port/glcdc_port.c:2063`、`src/port/lvgl_port_mtk3.c:217` | ISR通知の観測数。0 Hzだけで物理出力停止を断定しない。underflow表示の帯域不足という文言も原因確定ではない |
| `display reg` | `src/port/glcdc_port.c:743`、呼出分岐2491 | FLM2、FLMRD、AB1、出力設定、クロック等を先に読み出してから出力。逐次読出しで非原子的。FLM2だけで実際のパネル受信を証明しない |
| `display fbstat` | 同1044、呼出分岐2496 | 両バッファのCPU読出し標本。描画中なのでフレーム混在、全画素検査ではない。volatile読出しだけでキャッシュ無効化は行わず、GLCDC側から見えるSDRAM内容と一致する保証には使わない |

dbufの取得中は1秒待ちでCPUを譲る（同639付近）。fbstatはロックなしの読出しループ
（同1077以降）であり、取得によるCPU／バス負荷はある。起動記録boottraceを必ず先に採る。
各コマンドの成功復帰はNT-ShellのCMD_OKへ戻る（同2486〜2499）。コマンドの成功自体は表示成功ではない。

## ユーザーによる追加取得

現行RTC_TRACEのまま、従来のPC同一ポート・ケーブルで行う。書換え不要。
RTC電池・スピーカー・時刻設定を途中で変えず、今回はtime setを実行しない。
まだ電源を切っていない起動があれば、その回から取得できる。
新たな起動は最大2回、OFF 30秒。白・正常が揃うまで無制限に繰り返さない。
これは症状の分類用で、白率や対策の合否を判定する10回試験の代替ではない。

各回、目視結果と判定秒数を控えてから、次を1行ずつ実行し、全文保存する。

```text
boottrace
display dbuf
display reg
display fbstat
```

最後に画面が最初の判定から変化したかを記録する。入力したコマンドから30秒で
プロンプトが戻らなければ、その回で停止し最終行を保存する。
blank/test/backlightなど表示を変更する操作は、この取得には含めない。
今回の接続がPC給電であること、RTC電池ON、スピーカー接続、測定前time setの有無も併記する。

## 取得後の判断

| 観測 | 次に絞る対象 |
|---|---|
| 白でFlushが進まない | 初回以降のLVGL実行・待ち・更新要求。静止画ならFlush 0だけでは異常判定しない |
| 白でVsync通知が進まない | GLCDC状態と割込み通知経路。物理波形との区別が必要 |
| 白に対応してエラー増加・レジスタ差・白一色標本がある | その差の生成経路。正常回とのFLM2のバッファ交替だけを異常扱いしない |
| 白でも両計数が進み、設定・標本にも説明できる差がない | #230の既報に近い。ソフトの待ち探索を繰り返さず、パネル端信号／駆動電源とSDRAM整合の未観測範囲へ進む |

最後の分岐でもパネル故障と断定しない。具体的な電圧／波形測定は、測定器・回路接続・
AC給電での取得方法を確定して別途設計する。今回のコマンド取得はPCのままでよい。
コード調査と手順策定まで完了。追加の実機データはまだない。
