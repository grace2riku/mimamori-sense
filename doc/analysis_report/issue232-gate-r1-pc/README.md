# #232 gate-r1：表示開始前の電源異常を観測

## 入力と確認

ユーザー添付をreceived.txtへ無改変保存。取得手順はPC接続の予備試験として案内したが、
添付自体に給電元・RTC電池・スピーカー・OFF時間の明記はない。AC白率との比較には使用しない。
1回目の画面は「白」と明記。2回目の画面分類は未記載であり、白と補完しない。

両起動のBOOTGATE232 v=23202、BOOTTRACE232 v=23201 fnv=3615F648はgate-r1配布識別と一致。
既存read_log.analyzeにgate-r1のexpected_fnvを明示して解析し、boot-1/2.jsonへ保存。
26スロット、記録24点、通番欠落なし。未記録は保持あり分岐で通らないPROVISION前後のみ。
トレースのfault=0は記録器の状態であり、U2保護状態ではない。

| 2 | HOLD | 4.79 V | 2.617 V | 判定対象外 |

1回目HOLDのTP4には単位が省略されているが、同じ電圧測定の文脈でVとして整理。
以前の正常動作時はPG=0 V、TP4=9.73 V（別起動）。
PGはPower GoodではなくQ1のゲート駆動。今回VDD/EN/VREFを同時には測っていないので、
以前の値を今回の同時測定として結合しない。

## 同一起動内の順序

| 記録 | 1回目 OS稼働時刻 | 2回目 OS稼働時刻 |
|---|---:|---:|
| HOLD到達 | 60 ms | 60 ms |
| アプリRTC初期化 | 460 ms | 460 ms |
| 再開要求・RUNNING・RESET開始 | 193400 ms | 102300 ms |
| GLCDC Open/Start | 193400 ms | 102300 ms |
| DISPLAY_READY | 193420 ms | 102320 ms |
| 最初のflush／バックライト要求 | 193460 ms | 102360 ms |
| 最初のVsync待ち復帰 | 193490 ms | 102390 ms |

時刻は10ms量子化。保留区間は約193.34秒／102.24秒。
測定の正確な時刻は未記載で、保留区間を通じて電圧がずっと同じだったとは主張しない。
DISPLAY_BEGIN→ENDは保留を含み、DWT epochも0→1なのでサイクル差から時間換算しない。
RESET/Open/Startはすべて再開後。GLCDC Open/Start、初期BufferChange、flushの記録済み戻り値は成功。
両回ともRTC保持判定true、RCR1/2/4=00/41/00、初期化は復帰している。

## 確定した範囲

**今回の診断起動2回では、RESETパルス／GLCDC Open・Start／最初の描画／バックライトON要求より前に、
PG HighかつAVDD低下が存在した。** 後続のLCD信号出力開始は、この先行した異常の発生に必要ではない。
保留後に表示処理を進めても正常な電圧に回復しなかった。

根拠:
- 診断コピー `e2studio_CPU0/Debug/issue232/gate-r1/e2studio_CPU0/src/lvgl_thread_entry.c:171` のwaitが、
  同172のglcdc_port_initより前。完了を記録してから同196のタッチ初期化へ進む。
- `scripts/issue232-gate/boot_gate.inc:23`以降のHOLD公開→イベント待ち→RUNNING。
- LCD初期化のRESETは通常ソース `e2studio_CPU0/src/port/glcdc_port.c:1945`、
  GLCDC Open/Startは `e2studio_CPU0/src/port/lvgl_port_mtk3.c:130,134`。
- U2配線・保護仕様のマスタは `../issue232-trace-r1-pc/u2-startup-timing-audit.md`。

PG Highと低いAVDDは保護停止と整合するが、VDD/ENのこの起動での状態や、
一度正常起動してから停止したかは今回の測定だけでは決まらない。
PGの再開前後の約0.2V差から供給電流・電源不足を断定しない。TP3/VDDの同時観測がない。

## 残る候補と次の境界

今回のHOLDはPOST_Cの200ms待ち・IOPORT設定・SDRAM・LVGL/Dave2D初期化を通った後。
RESETはIOPORT設定でLowになった状態を保ち、カメラ・AI・RTC・音声などの他タスクは動く。
したがって次を除外できない。

1. U2の給電直後の起動失敗、電源過渡、部品／負荷／フィードバック系の条件。
2. IOPORT設定時のRESET Lowやピンの切替、SDRAM等の初期化に伴う負荷・ノイズ。
3. 保留中に動作する他タスクによる影響。RTC処理も保留中に実行済み。

この診断では長時間RESET Lowに保つため、通常版と同一の原因・白率を保証しない。
2回で白率を評価しない。一方、2回とも先行する電源異常を観測できたため、gate-r1を
追加で繰り返したり、GLCDC後の待ちを延ばしたりする必要は現時点ではない。

次の切り分け境界は **R_IOPORT_Openより前と後**。
その前は既存UARTピン初期化も済んでいないため、今回と同じコンソール再開方式をそのまま前へ移せない。
別診断の設計では、コンソールに依存しない保留・測定手順と、追加待ちそのものの影響を明示する必要がある。
本報告では新しいファーム変更・書込みは行っていない。
