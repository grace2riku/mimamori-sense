# F-003-3a: 転倒検出モデル精度改善計画

Issue #101: 転倒検出モデルの精度改善 (mAP 67.8% -> 90% 目標)

## 1. 現状分析

### 1.1 現在のモデル性能

| メトリクス | 現在値 | 目標値 | 差分 |
|-----------|--------|--------|------|
| mAP@0.5 | 67.8% | 90%以上 | -22.2pt |
| mAP@0.5:0.95 | 42.4% | -- | -- |
| Precision | 80.4% | -- | -- |
| Recall | 59.3% | 80%以上 | -20.7pt |

### 1.2 現在の学習構成

| パラメータ | 値 |
|-----------|------|
| モデル | YOLOv8n (COCO事前学習済み) |
| 入力サイズ | 192x192x3 (RGB) |
| エポック数 | 100 |
| バッチサイズ | 64 |
| 学習率 | SGD, lr0=0.01, lrf=0.01 |
| ウォームアップ | 3エポック |
| データ拡張 | mosaic=1.0, fliplr=0.5, scale=0.5, degrees=10, hsv_v=0.4 |

### 1.3 データセット構成

| Split | 画像数 |
|-------|-------|
| Train | 32,853 |
| Val | 2,368 |
| Test | 2,369 |

データソース: COCO Person + Roboflow Fall Detection (オフラインaugmentation済み)

### 1.4 課題の根本原因分析

**Recall 59.3% が低い主な原因:**

1. **学習不足**: 100エポックでは32,853枚のデータセットに対して学習が収束しきっていない可能性が高い。特にYOLOv8nは小型モデルのため、十分な学習エポック数が必要。

2. **入力サイズが小さい**: 192x192は一般的なYOLOの入力サイズ (416x416, 640x640) と比較して非常に小さい。小さい人物や遠くの人物が潰れてしまい、検出できない。

3. **最終学習率が高い**: `lrf=0.01` は最終学習率が初期の1%までしか下がらない。`lrf=0.001` (初期の0.1%) にすることで、学習終盤の微調整精度が向上する。

4. **データ拡張が限定的**: mixup や copy_paste などの高度な拡張が未使用。scale=0.5 も控えめで、スケール変動への対応が不十分。

## 2. 改善計画

### 2.1 実験計画

3つの段階的な実験を行い、各改善要素の効果を切り分ける。

#### 実験A: エポック数増加 (最小限の変更)

目的: エポック数増加だけでどこまで改善するか確認。

| パラメータ | 旧値 | 新値 |
|-----------|------|------|
| epochs | 100 | 300 |
| lrf | 0.01 | 0.001 |
| warmup_epochs | 3.0 | 5.0 |
| cos_lr | False | True |
| patience | 50 | 100 |
| close_mosaic | 10 | 30 |
| imgsz | 192 | 192 |

期待される効果:
- mAP@0.5: 67.8% -> 75-80%
- Recall: 59.3% -> 65-75%
- 学習時間: T4 GPU で約3時間

#### 実験B: 入力サイズ拡大

目的: 入力サイズ拡大のRecall改善効果を確認。

| パラメータ | 実験Aから変更 |
|-----------|---------------|
| imgsz | 192 -> 320 |
| batch | 64 -> 32 |

期待される効果:
- mAP@0.5: 80% -> 85-90%
- Recall: 65% -> 75-85%
- 入力サイズ拡大はモデルの重みサイズに影響しない
- 学習時間: T4 GPU で約5時間

#### 実験C: データ拡張強化 (フル改善)

目的: 全ての改善を適用した最高精度を確認。

| パラメータ | 実験Bから変更 |
|-----------|---------------|
| mixup | 0 -> 0.15 |
| copy_paste | 0 -> 0.1 |
| scale | 0.5 -> 0.9 |
| translate | 0.1 -> 0.2 |
| degrees | 10 -> 15 |

期待される効果:
- mAP@0.5: 85% -> 90%+
- Recall: 75% -> 80%+
- 学習時間: T4 GPU で約6時間

### 2.2 パラメータ変更の根拠

#### エポック数 (100 -> 300)
- YOLOv8n + 32K画像のデータセットでは、300エポックがUltralyticsの推奨値に近い
- 100エポックではloss曲線がまだ下降傾向にある可能性が高い
- patience=100 で早期終了を設定しているため、収束済みなら自動停止する

#### Cosine学習率スケジュール
- 線形減衰より滑らかな学習率変化で、学習終盤の精度が向上
- 最終学習率 (lrf=0.001) でlr0の0.1%まで下がり、微調整が効く

#### close_mosaic (10 -> 30)
- mosaic augmentation解除後のエポック数を増加
- mosaic無しの通常データで微調整する期間を延ばし、最終精度を向上

#### 入力サイズ (192 -> 320)
- 192x192では人物が6x6ピクセル程度に縮小される場合がある
- 320x320にすることで約2.8倍の面積が確保でき、小人物のRecall改善に直結
- 重要: 入力サイズはモデルの重みサイズ (INT8 KB) に影響しない
- 推論時のテンソルアリーナサイズは入力サイズに比例して増加する

#### mixup (0 -> 0.15)
- 2つの画像を重ね合わせることで汎化性能が向上
- 過学習を抑制し、未見の人物ポーズへの対応力が向上

#### copy_paste (0 -> 0.1)
- 物体検出に特化したaugmentation
- 人物のインスタンスを別の画像にペーストし、出現パターンを多様化

### 2.3 F-003-3b (モデル小型化) との関係

入力サイズとモデルサイズの関係:
- **モデルの重みサイズ** (INT8 KB): 入力サイズに依存しない。YOLOv8nは入力192でも320でも同じ約3,149KB
- **テンソルアリーナサイズ**: 入力サイズに比例。192x192x3=110KBの入力バッファ vs 320x320x3=307KB
- **推論速度**: 入力サイズが大きいほど遅くなる

戦略:
1. まず精度改善 (本Issue) で最高精度を確認
2. 次にモデル小型化 (F-003-3b) でサイズ削減
3. 精度とサイズのトレードオフの最適点を見つける
4. デプロイ時の入力サイズはArena制約と推論速度を考慮して決定

## 3. 実行手順

### 3.1 ノートブックの使い方

ファイル: `dataset/scripts/train_yolov8_improved_colab.ipynb`

1. Google Colabで開く (GPU: T4)
2. Step 3のセルで `EXPERIMENT = 'A'` を設定
3. 全セルを実行
4. Step 5で結果を確認
5. 目標未達の場合、`EXPERIMENT = 'B'` or `'C'` に変更して再実行

### 3.2 推奨実験順序

```
実験A (300ep, 192) -- エポック数増加の効果確認
  |
  +--> 目標達成 --> 完了 (最小変更で達成)
  |
  +--> 目標未達 --> 実験B (300ep, 320) -- 入力サイズ拡大の効果確認
                      |
                      +--> 目標達成 --> 完了
                      |
                      +--> 目標未達 --> 実験C (300ep, 320, aug強化) -- フル改善
                                        |
                                        +--> 目標達成 --> 完了
                                        |
                                        +--> 目標未達 --> 追加対策検討
```

### 3.3 追加対策 (実験Cでも目標未達の場合)

1. **エポック数の更なる増加**: 400-500エポック
2. **YOLOv8sの検討**: YOLOv8n (3M params) -> YOLOv8s (11M params) で精度向上 (ただしサイズ3-4倍)
3. **データセット追加**: 転倒シーン、暗い環境、小さい人物の画像を追加
4. **Multi-scale学習**: 複数の入力サイズで学習
5. **Label smoothing**: label_smoothing=0.05 で過学習を抑制
