## 要求事項詳細

### 顔認識サンプルプログラムの解析
- 顔認識サンプルプログラム(application_examples/face_detectionディレクトリ以下)を解説してください。
  - ファイルツリーを示してください。
  - マルチコアのプロジェクトか?
  - 使用しているEK-RA8P1のハードウェアリソースは何か。設定しているペリフェラルは何か?何のペリフェラルをなぜ設定しているのか?
  - カメラ撮影画像をAIの認識に使っていると思うがカメラ撮影画像から顔認識するまでの流れを解説してください。静的な視点（必要なソフトモジュール、ソフトウェアモジュールの構造・階層構造）、動的な視点（カメラ撮影画像で顔認識するまでのシーケンス）で解説してください。
  - LCDへの表示はどのように実装しているか。LVGLを使用しているか?使用している場合、表示パイプライン（カメラ画像取得からLCD表示まで）を解説してください。

### AIモデルの解析
- 使っているAIモデルについて解説してください。
  - 該当ファイルはどれか
  - ツールで自動生成されているファイルはどれか
  - プログラムからどのように利用されているか。プログラムとのインターフェースはどうなっているか

### 画像分類サンプルプログラムの解析
- 画像分類サンプルプログラム(application_examples/image_classificationディレクトリ以下)を解説してください。
  - ファイルツリーを示してください。
  - 顔認識サンプルプログラムとの構造の違いを解説してください。
  - 転倒検出は「転倒している/していない」の分類問題として捉えることもできる。画像分類サンプルプログラムの方が転倒検出に適しているか、顔認識サンプルプログラムと比較して評価してください。

### FreeRTOSとの連携およびμT-Kernel 3.0への移植観点
- 顔認識サンプルプログラムがFreeRTOSをどのように使用しているか解説してください。
  - FreeRTOSのどの機能（タスク、セマフォ、キュー、タイマー等）を使用しているか
  - RTOS依存部分はどのファイル・関数に集中しているか
- 最終的にFreeRTOSはμT-Kernel 3.0に置き換える予定である。FreeRTOSからμT-Kernel 3.0への移植ポイントを解説してください。

### 性能特性
- 顔認識サンプルプログラムの性能特性を解説してください。
  - AI推論時間はどの程度か（設計値・実測値があれば記載）
  - カメラ撮影からLCD表示までのフレームレートはどの程度か
  - mimamori-senseのKPI（フレームレート30fps以上、AI推論時間5ms以内）と比較して達成可能か

### mimamori-senseへの流用可能性
- mimamori-senseでは顔認識ではなく、人の転倒を検出することが目的です。顔認識サンプルプログラムを流用できそうか?流用できる場合、以下の観点で移植の手順を示してください。
  - カメラ撮影パイプラインはそのまま流用可能か
  - AIモデルの差し替え方法（顔認識モデル→転倒検出モデル）
  - 推論前後の画像前処理・後処理の変更箇所
  - FSP設定（configuration.xml）の変更有無
