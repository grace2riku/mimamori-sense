## 最初の取得試運転（最大2起動）

1. **RTC_TRACE_CPU0.mot と RTC_TRACE_CPU1.motの1組**を書き込み、RFPで両方をベリファイします。
2. RTC電池ON・スピーカー接続ありを維持します。J10を従来のPCの同じポート／ケーブルへ接続し、115200 baud、8N1でコンソールを使用します。
3. 時刻が既に設定済みなら変更しません。必要な場合のみ測定前の準備として`time set`を実施し、その有無を記録します。
4. OFF 30秒→ON。まず表示を「正常／全面白／黒／カラーバー」に分類し、判定までのおおよその秒数を控えます。
5. プロンプトが使えたら、設定変更や表示操作より先に **`boottrace`** を実行します。`BOOTTRACE232`から`BOOTTRACE232 END`まで全文を保存してください。
6. 電源投入から30秒で取得できない場合は、その回で中断します。電源を切る前に、表示・LED・コンソール最終行を報告してください。RAMの記録は電源断で失われます。
7. 1回目が取得できた場合のみ、同じ条件でもう1回（OFF 30秒）実施します。正常と白が両方出るまで繰り返す必要はありません。

返す内容: 各回の表示分類、判定までの秒数、boottrace全文、準備時にtime setを実行したか。
`seq=0`はそのsnapshot時点で未記録です。エラーでもログを加工せず、そのまま残してください。
PC接続はログ取得の試運転で、ACでの白5/10との白率比較には使用しません。
AC給電を維持したままの取得方法と、その後の比較測定は、この2回の結果を見て別途決定します。

## ログの意味

- `seq`: OS後の記録順。10ms刻みのOS時刻が同値でも、通番で記録点の順序を比較できます。
- `BRANCH result=1`: 実際のSTART/HR24判定が初期化済みだった。電池保持の完全な検証とは異なります。
- `BRANCH aux`: 下位からRCR1、RCR2、RCR4の各8bit。`extra`: 下位SOSCCR、次の8bitがSOMCR。BSP操作後の値です。
- `PROVISION`: RTCクロック源設定／リセットAPI区間。内部のどのレジスタ待ちで停止したかまでは区別しません。
- `GET`: 初期化時のRTC読出し。`SYNC`: OS時刻同期処理。各ENDは処理から戻った印で、SYNC/PROVISIONのresult=0は戻り値検査を新設したものではありません。
- `INITIAL_BUFFER`: 初期の黒バッファ設定。`FLUSH`: 最初の最終領域での描画済みバッファ提出。別の記録点です。
- `BACKLIGHT`: 点灯要求のAPI復帰。`WAIT`: 最初の最終領域Vsync待ち。これらからパネルの表示成功は断定できません。
- APIのresultは原則0が成功、ただしDISPLAY_ENDはbool由来で1が成功です。未記録行のresultには意味がありません。
- DWTは32bitで周回し、AIがリセットするためepochも記録します。解析器は世代跨ぎ・周回不明・カウンタ停止等の差分を棄却します。
- サイクル差は他タスク／ISRの実行を含み、sleep中等に止まる可能性があります。一般区間の壁時計時間やCPU専有時間とは呼びません。OS差は10ms量子化されています。

## 開発者用

同ディレクトリの`build.py`を実行すると診断用コピーだけを生成します。既存runは上書き禁止です。
`--resume`は未完成runの再コンパイル専用。完成済み成果物の変更には使えません。
`verify.py`はMOTを生成し、配布CPU1とのペア・配置・ソース入力ハッシュを検証します。
`python test_read_log.py`は12件の解析検証を実施します（合成ログであり実機測定ではありません）。

ログ解析例（リポジトリルートから）:

```text
python scripts/issue232-trace/read_log.py boot-1.txt --manifest e2studio_CPU0/Debug/issue232/trace-r1/artifacts/build-verification.json
```

初期化全体はロック取得待ちも含みます。上限なしの下位API待ち、NT-Shell停止で取得不能となる制約、
再リンクによる観測影響は `doc/design/issue-232.md` を参照してください。
